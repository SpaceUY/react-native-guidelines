# EN/ES i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a Spanish translation of every page on the React Native Guidelines Jekyll site, reachable under `/es/`, with a working language switcher and a nav that never mixes languages.

**Architecture:** Manual, plugin-free i18n. English stays at its current unprefixed URLs; Spanish content lives in a path-for-path mirror under `es/`. `_config.yml` assigns `lang: en` / `lang: es` via `defaults:` scoped by path — no per-file front matter needed. Three theme files are forked (copied into this repo's own `_layouts`/`_includes`, which Jekyll uses to shadow the `just-the-docs` gem's files of the same relative path) with minimal, targeted diffs: per-page `<html lang>`, a language-filtered left nav, and a language switcher. Two more theme override points (already provided empty by the gem) get lang-aware UI strings. Callout titles (Note/Tip/etc.) are translated per-page using `just-the-docs`' existing manual-title callout syntax — no theme change needed for that part.

**Tech Stack:** Jekyll 4.3, `just-the-docs` 0.10.1 (pinned gem), kramdown, Ruby (use Homebrew's Ruby at `/opt/homebrew/opt/ruby/bin`, not the system Ruby 2.6 — see Global Constraints).

Full design rationale: `specs/2026-08-31-i18n-en-es-design.md`.

## Global Constraints

- No new Jekyll plugins/gems. Every change is either a config tweak or a same-path override of an existing theme file.
- Ruby: the system Ruby (`/usr/bin/ruby`, 2.6.10) cannot run this project's pinned `bundler` (needs 3.3+). Every command in this plan that touches `bundle`/`jekyll` must be prefixed with:
  ```bash
  export PATH="/opt/homebrew/opt/ruby/bin:$PATH"
  ```
- Repo root: `/Users/matias/Documents/GitHub/spacedev-react-native-guidelines`.
- URL structure: English unprefixed (`/`, `/docs/**`), Spanish under `/es/` mirroring the same relative paths (`/es/`, `/es/docs/**`). This mirror must stay exact — the language switcher (Task 4) computes the equivalent URL by adding/removing the `/es` prefix, with no page-to-page mapping file.
- Internal cross-references in this site's prose are never hyperlinks — they're bolded plain-text mentions of a page's title (confirmed via a repo-wide grep in the design phase: zero relative/internal markdown links exist in `docs/` or `index.md`). Translating a cross-reference means translating that bolded text to the target page's Spanish title from the glossary below — never inventing a link.
- Don't translate: code blocks, shell commands, file paths, package/library/product names (`TypeScript`, `NativeWind`, `Expo Router`, `Firebase`, `EAS`, etc.), `site.title`.
- Callout conversion (every language-appropriate callout in an `es/` file uses the **manual title** form, not the shorthand — the shorthand's title text is baked into site-wide CSS in English and can't vary per page):

  Spanish manual-title form (use in `es/docs/`):

  Class → Spanish title: `note` → **Nota**, `tip` → **Consejo**, `important` → **Importante**, `warning` → **Advertencia**. (`highlight` is unused anywhere in this site today — no title needed if it's ever added.)

**Correction found during Task 6 execution:** the filter above is necessary but not sufficient. `just-the-docs` invokes `site_nav.html` via Jekyll's `include_cached` tag (from the `jekyll-include-cache` gem) at three call sites — `components/sidebar.html`, `components/breadcrumbs.html`, `components/children_nav.html`. That tag's cache key is `hash(include path) + hash(explicit params passed in the include tag)` — it does **not** vary by ambient context like `page.lang`. None of the three call sites passed any language-sensitive param, so the *first* page built (any language) rendered and cached the nav once, and every other page — regardless of its own `page.lang` — got that same cached HTML back. This only became visible once a second language's content existed (Task 6's home page still showed the English nav).

Fix: fork those three files too, adding `lang=page.lang` to each `include_cached components/site_nav.html ...` call. `jekyll-include-cache` hashes that extra param into the cache key, so each language now gets its own cache entry. `page` is still in scope inside the include normally (Liquid includes aren't sandboxed from ambient variables) — the caching layer was the only thing short-circuiting a fresh render.

```markdown
# React Native Guidelines

Una guía práctica y con criterio propio sobre cómo construimos apps de
**React Native + Expo**. Existe para que cualquier proyecto se sienta
familiar: misma estructura, mismas herramientas, mismo flujo de release.
¿Nuevo por acá? Empezá por **Primeros Pasos** y leé de principio a fin.

Las guías están para ayudar, no para imponer. Si algo no está claro o no
estás de acuerdo, abrí un PR — esta guía debe evolucionar con nosotros.

## Cómo usar esta guía

- **¿Nuevo en un proyecto?** Primeros Pasos → Arquitectura del Proyecto.
- **¿Construyendo una funcionalidad?** Andá directo a **Desarrollo de
  Funcionalidades**.
- **¿Por lanzar un build?** Todo lo que necesitás está en **Compilación y
  Distribución**.
- **¿Buscando algo puntual?** Usá el buscador (arriba de la página) o la
  **Referencia**.
- **¿Usando Claude Code (u otro asistente de IA)?** Empezá por **Claude** —
  el prompt de arranque y la plantilla de `CLAUDE.md`.

## Qué vas a encontrar

| Sección | Vas a aprender |
| --- | --- |
| Primeros Pasos | Herramientas, crear/clonar un proyecto, ejecutarlo |
| Arquitectura del Proyecto | Cómo organizamos el código y tomamos decisiones |
| Desarrollo de Funcionalidades | Navegación, estado, networking, formularios, estilos y más |
| Entorno y Configuración | Variables de entorno y builds por ambiente |
| Calidad de Código | TypeScript, linting, testing, CI |
| Compilación y Distribución | Builds internos, dispositivos y lanzamientos a las tiendas |
| Buenas Prácticas | Convenciones y errores comunes |
| Referencia | Glosario, hojas de referencia rápida y links |
| Claude | Cómo preparar a Claude Code para que siga esta guía en cada proyecto |
```
